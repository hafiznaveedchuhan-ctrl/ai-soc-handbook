# Playbooks

* [Playbook: brute-force logon attempts](brute-force.md) - L1 steps for a burst of failed Windows logons — confirm the pattern, collect counts and sources, enrich the source IP, decide guessing vs spraying vs benign, and escalate on success or privileged targets.
* [Playbook: successful logon after failures](success-after-failures.md) - L1 steps when an account that just produced many failed logons then logs on successfully — the moment a brute-force attempt may have worked; always an immediate escalation.
* [Playbook: new local account created](new-local-account.md) - L1 steps for event 4720 — identify who created which account, check its attributes against Microsoft's anomaly list, look for the command that created it and any group membership that followed.
* [Playbook: account added to Administrators](added-to-admin-group.md) - L1 steps for event 4732 into the local Administrators group (Wazuh 60154) — who added whom, whether it was planned, and why it is an immediate escalation when it was not.
* [Playbook: Security audit log cleared](audit-log-cleared.md) - L1 steps for event 1102 — who cleared the Security log from which session, what happened just before, and why it is escalated unless a documented maintenance reason exists.
* [Playbook: suspicious PowerShell](suspicious-powershell.md) - L1 steps for a suspicious PowerShell alert — read the full command line (Sysmon 1 / 4688) and script block (4104), check the parent process and what ran next, and decide using MITRE's PowerShell detection chain.
* [Playbook: new service or scheduled task](new-service-or-scheduled-task.md) - L1 steps for a new service (4697 / 7045) or scheduled task (4698) — check the binary path and task location against Microsoft's guidance, find who created it, and escalate on unexpected persistence.
* [Playbook: account lockout storm](account-lockout-storm.md) - L1 steps when many 4740 lockouts arrive together — tell a stale-password device from password guessing or spraying, using the Caller Computer Name, the 4625/4771 failures behind the lockouts and Wazuh 60115.
* [Playbook: port scan](port-scan.md) - L1 steps for a port or service scan — identify the scanning host and process, separate an authorised scanner from an intruder, and check whether anything after the scan succeeded.
* [Playbook: file integrity (FIM) or malware alert](fim-or-malware-alert.md) - L1 steps for Wazuh FIM alerts (550 checksum changed, 553 deleted, 554 added) and rootcheck anomalies (510) — what changed, who changed it, and whether the change was expected.
