================================================================
1. GOAL OF PHASE 2
================================================================
Turn this fresh KSoR scaffold into "SOC Triage Handbook" (machine name soc-handbook), a governed
System of Record for SOC Level-1 analyst operations: PRIMARILY the triage of SIEM/Wazuh security
alerts from Windows, Sysmon and Linux hosts, and ALSO the fundamentals an L1 analyst needs to triage
(networking, common attacks, phishing email analysis and SPF/DKIM/DMARC, the NIST incident response
lifecycle, security controls and log sources, IOCs and basic threat intelligence, Active Directory
basics). It declines malware reverse engineering, penetration testing/exploitation how-to,
legal/compliance advice, vendor pricing and anything outside SOC L1 operations. One
source serves two readers: SOC analysts on a static website, and the soc-worker AI agent (Phase 3)
over MCP with cited retrieval and honest abstention. Every page is drafted from Tier 1 official
sources (Tier 2 only where Tier 1 is silent, labelled secondary) or from Naveed's confirmed
interview answers, starts as draft, and becomes stable only when Naveed reads and approves it. The AI
suggests, a human decides; the record is read-only to agents and never holds client data. MCP
serving comes early (right after Wave 1 of the corpus) because Phase 3 depends on it; UI and auth
follow. Work follows SDD (constitution, spec, plan, tasks, implement, verify) with ADRs and PHRs,
using only free tiers.

8. RISKS AND HOW THEY ARE AVOIDED
================================================================
- Invented facts (IDs, codes, rule numbers): only from opened Tier 1 pages; otherwise TODO-VERIFY and
  the page stays draft.
- Invented CLI flags: every ksor command verified with --help (section 5).
- Copied text / MITRE terms of use: own words, attribution footnotes.
- Wrong Wazuh rule IDs: only from the pinned ruleset files, with file links.
- Privacy: no former employer or client name in knowledge/; interview source string fixed.
- ksor-record-empty if starters deleted too early: first own doc approved before deleting.
- ksor-generated-stale after editing a stable page: move generated.at forward and re-approve.
- Quiz audit refusals (answer bias, length bias, runs): spread answer positions, equal option lengths.
- Dangling links Wave 1 -> Wave 2: links added only when the target exists.
- Floor measured on Wave 1 goes stale after Wave 2: calibrate --check, recalibrate on WATCH.
- Draft-only build looks empty: expected; explained in LEARNING.md.
- Free-tier Gemini rate limits: incremental ingest, our own query file for calibration.
- Secret leakage: .env never opened or committed; gitleaks in CI.
